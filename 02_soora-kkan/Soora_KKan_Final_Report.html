1. 프로젝트 기획 배경 및 핵심 의도

사내 야유회에서 진행되는 조별 요리 경연대회는 팀원 간의 소통과 단합을 증진시키는 핵심 이벤트입니다. 기존의 주관적이고 지연되기 쉬운 수기 채점 방식을 탈피하여 스마트폰 기반의 실시간 심사 PWA 앱을 구축하고, AI 시각 분석과 위트 있는 심사위원 페르소나를 결합하여 행사 자체의 공정성과 재미를 극대화하고자 기획되었습니다.

  • 네이밍 아이덴티티: 전통 궁중의 권위를 상징하는 '수라간'에 '깐깐한 팀장'의 시각을 결합한 'SOORA-KKAN'.
  • 모바일 최적화 (PWA): 별도 앱스토어 설치 없이 스마트폰 브라우저에서 '홈 화면에 추가'하여 풀스크린 네이티브 앱처럼 동작.
  • 현장 리스크 제로화: 야외 통신망 불안정 및 구글 클라우드 트래픽 급증에 대비한 3중 안전망 설계.

3. 실전 필드 테스트 기반 주요 트러블슈팅 및 고도화 내역

1. 모바일 앨범 선택 불가 및 카메라 직행 현상 해결

현상: 모바일 기기에서 사진 버튼 터치 시 앨범 선택 창이 뜨지 않고 카메라 앱으로만 강제 연결됨.
원인: <input capture="environment"> 단일 태그로 구성 시 일부 모바일 OS가 갤러리 접근을 차단함.
해결: [📸 카메라 직접 촬영]과 [🖼️ 갤러리/앨범 선택] 전용 인풋을 2개로 물리 분리하여 직관적인 UX 구축.

2. 비요리(문구류/마우스) 촬영 시 심사 왜곡 방지 및 진위 판별 로직 탑재

현상: 책상 위 마우스나 문구류를 촬영해도 "고기의 마이야르 반응이 우수하다"는 식의 기본 칭찬이 출력되는 심각한 심사 왜곡 발생.
원인: API 예외 시 단순 더미 텍스트를 반환하는 구조 및 음식 여부를 확인하지 않는 단편적 프롬프트.
해결: 프롬프트 1단계에 음식 진위 검증(is_food boolean 체크)을 강제. 음식이 아닐 경우 비전 점수를 즉시 0점 박탈하고 "이것은 요리가 아니라 [사물명]입니다! 심사 대상이 아닙니다."라고 반려하도록 엄격화.

3. 구글 서버 트래픽 폭주(High Demand 503) 대응 3중 Failover 아키텍처

현상: 최신 모델에 글로벌 트래픽이 몰릴 때 503 Service Unavailable이 발생하며 평가가 지연됨.
해결: gemini-3.1-flash-lite → gemini-3.5-flash → gemini-3.8-flash 순으로 자동 순차 재시도하는 Failover 루프를 구현하고, 구글 전체 장애 시에도 앱이 멈추지 않도록 비상 로컬 판정 엔진을 3차 안전장치로 완비.

4. 연속 평가 시 브라우저 용량 초과(QuotaExceededError) 먹통 현상 해결

현상: 4개 이상의 조를 연속 채점하여 저장할 때 화면이 검은색으로 멈추고 저장이 롤백됨.
원인: 스마트폰 원본 고화질 사진(장당 5~10MB)을 그대로 LocalStorage(최대 5MB 한도)에 넣어 메모리 크래시 발생.
해결: 브라우저 Canvas를 통해 사진 업로드 즉시 가로 600px, 용량 50~70KB 수준으로 90% 이상 자동 압축(JPEG 0.65)하여 영구 저장 안정성 확보.

5. PWA 강력 캐싱 대응 '강제 새로고침(Hard Refresh)' 기능 탑재

현상: 서버에 신규 코드를 배포해도 모바일 홈 화면 앱에서 이전 자바스크립트 캐시를 물고 있어 업데이트가 반영되지 않음.
해결: 상단 헤더에 서비스 워커 및 브라우저 캐시 스토리지를 즉시 날리고 강제 새로고침하는 handleHardRefresh() 버튼 구현.

  • Dual Engine: 구글 Gemini 멀티모달 VLM 정밀 시각 분석 + 오프라인 비상 휴리스틱 엔진 결합.
